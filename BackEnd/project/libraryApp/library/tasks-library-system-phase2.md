# 🚀 تاسكات المرحلة الثانية: رفع مستوى المشروع (Advanced & Polish)

> إنت خلصت الـ Core Features، دلوقتي الوقت المرحلة اللي بتفرق فعليًا في المقابلات والـ CV.
> مش شرط تعمل كل حاجة هنا، لكن كل تاسك تضيفه بيزود من "وزن" المشروع.

---

## 🔐 Phase 11: الأمان (Security)

### Task 11.1: حماية من الهجمات الشائعة
- [ ] استخدام `helmet` لحماية الـ HTTP Headers
- [ ] استخدام `express-rate-limit` لمنع الـ Brute Force على تسجيل الدخول
- [ ] استخدام `express-mongo-sanitize` لمنع NoSQL Injection
> 💡 تلميح: طبّق الـ rate limit على route الـ login بالذات بشكل أشد (مثلاً 5 محاولات كل 15 دقيقة)، ده أهم حاجة عملياً.

### Task 11.2: CORS بشكل صحيح
- [ ] إعداد `cors` بحيث يقبل بس الدومينات المسموح بيها بدل `*`
> 💡 تلميح: خزّن الدومينات المسموحة في `.env` عشان تقدر تغيّرها بين بيئة التطوير والإنتاج بسهولة.

### Task 11.3: Refresh Tokens
- [ ] إضافة Refresh Token جنب الـ Access Token
> 💡 تلميح: الـ Access Token يبقى عمره قصير (زي 15 دقيقة) والـ Refresh Token يتخزن كـ httpOnly cookie، ده بيتسأل فيه كتير في الإنترفيوهات.

## ✅ Phase 12: الاختبارات (Testing)

### Task 12.1: Unit Tests
- [ ] استخدام `Jest` لاختبار دوال منطقية (زي حساب الفاتورة أو التحقق من المخزون)
> 💡 تلميح: ابدأ بأبسط دالة عندك، الهدف مش تغطية 100% لكن إنك تفهم مبدأ الـ Testing وتقدر تتكلم فيه.

### Task 12.2: Integration Tests
- [ ] استخدام `Supertest` لاختبار الـ Endpoints فعليًا (زي تسجيل مستخدم ثم تسجيل دخول)
> 💡 تلميح: استخدم قاعدة بيانات تجريبية منفصلة (Test DB) أو `mongodb-memory-server` عشان متبوظش بياناتك الحقيقية.

---

## ⚡ Phase 13: الأداء (Performance)

### Task 13.1: الـ Indexing في MongoDB
- [ ] عمل Index على الحقول اللي بتتبحث بيها كتير (اسم الكتاب، الإيميل)
> 💡 تلميح: استخدم `text index` على حقل اسم الكتاب لو عايز بحث نصي أسرع وأذكى من الـ RegExp.

### Task 13.2: الـ Caching
- [ ] استخدام Redis أو حل بسيط لعمل Cache لبيانات بتتغير قليل (زي إعدادات المكتبة أو الكتب الأكثر مبيعًا)
> 💡 تلميح: ابدأ بسيط، ممكن Caching في الميموري لبيانات صغيرة قبل ما تدخل في Redis لو الوقت ضيق.

### Task 13.3: Pagination محسّنة
- [ ] التأكد إن كل الـ lists (كتب، طلبات، عملاء) فيها pagination من الأساس
> 💡 تلميح: رجّع مع كل response معلومات زي `totalItems`, `totalPages`, `currentPage` عشان الفرونت إند يقدر يبني عليها.

## 📝 Phase 14: التوثيق الاحترافي (Documentation)

### Task 14.1: Swagger / OpenAPI
- [ ] توثيق كل الـ Endpoints باستخدام `swagger-jsdoc` و `swagger-ui-express`
> 💡 تلميح: ده بيدي انطباع احترافي جدًا في الـ CV، لأنه بيوضح إنك فاهم معايير التوثيق المستخدمة في الشركات.

### Task 14.2: README احترافي
- [ ] وصف المشروع، الـ Tech Stack، خطوات التشغيل، الـ ERD (العلاقات بين الموديلات)
- [ ] لينك للـ API documentation والـ Demo لو موجود
> 💡 تلميح: ضيف صورة أو مخطط بسيط (Diagram) للعلاقات بين الموديلات، بصريًا بيفرق كتير في أول انطباع.

## 🌟 Phase 15: مميزات إضافية تفرق في الـ CV (Nice to Have)

### Task 15.1: نظام تقييمات ومراجعات (Reviews)
- [ ] العميل يقدر يقيّم الكتاب بعد الشراء (rating + comment)
> 💡 تلميح: احسب متوسط التقييم (`averageRating`) وخزّنه في الكتاب نفسه بدل ما تحسبه كل مرة من كل الـ reviews.

### Task 15.2: نظام كوبونات وخصومات
- [ ] Model للكوبونات (كود، نسبة خصم، تاريخ انتهاء)
> 💡 تلميح: تحقق من صلاحية الكوبون وتاريخ انتهائه وقت الـ Checkout بس، مش وقت عرضه.

### Task 15.3: الإشعارات (Notifications)
- [ ] إرسال إيميل للعميل عند تغيير حالة الطلب (باستخدام `nodemailer`)
> 💡 تلميح: ابدأ بإيميل بسيط عند "تم الشحن" و"تم التسليم"، مش لازم تغطي كل الحالات من الأول.

### Task 15.4: الـ Logging
- [ ] استخدام `winston` أو `morgan` لتسجيل الطلبات والأخطاء في ملفات Log
> 💡 تلميح: فرّق بين log للتطوير (يظهر في الـ Console) ولوج للإنتاج (يتخزن في ملف)، ده بيتسأل عنه كتير في مقابلات الـ Backend.

## 🎯 Phase 16: CI/CD & Git Workflow

### Task 16.1: Git بشكل احترافي
- [ ] Commits واضحة ومنظمة (Conventional Commits)
- [ ] Branches منفصلة للفيتشرز (`feature/orders`, `feature/auth`, ...)
> 💡 تلميح: حتى لو بتشتغل لوحدك، اتعامل مع الـ Git كإنك في فريق — ده بيبان واضح جدًا لأي حد يفتح الـ Repo بتاعك.

### Task 16.2: GitHub Actions بسيط
- [ ] عمل workflow يشغّل الـ Tests تلقائيًا مع كل push
> 💡 تلميح: ابدأ بأبسط workflow (تشغيل `npm test` بس)، ده كافي إنك تقول في الـ CV "عندي CI/CD Pipeline".

## 📌 إزاي تختار إيه تعمل من دول؟

مش لازم تعمل كل حاجة. لو وقتك محدود، رتّب أولوياتك كده:

1. **الأمان (Phase 11)** — أهم حاجة، أي backend developer المفروض يعرفها.
2. **التوثيق (Phase 14)** — أرخص حاجة في الوقت وأعلى حاجة في التأثير على الـ CV.
3. **الاختبارات (Phase 12)** — حتى لو بسيطة، بتفرق كتير.
4. **مميزة واحدة أو اتنين من Phase 15** — عشان المشروع ميبانش "نموذجي" زي أي مشروع تعليمي تاني.
5. **الأداء والـ CI/CD** — لو فاضلك وقت وعايز تتميز أكتر.
